# IRISA Mail — iOS builds and TestFlight

The iOS app is generated by Expo prebuild and built by
[release-ios.yml](../.github/workflows/release-ios.yml) on a macOS runner.
The ios/ directory is gitignored and regenerated for every build. Native iOS
changes belong in app.config.js or a config plugin, never in a local generated
ios/ directory.

Without Apple signing secrets, the workflow performs an unsigned compile check.
It does not produce an installable IPA or upload to TestFlight.

## 1. Apple Developer account and Team ID

An active Apple Developer Program membership is required.

Find the 10-character Team ID at developer.apple.com → Account → Membership
details. Set it as APPLE_TEAM_ID in the local build environment and as the
APPLE_TEAM_ID GitHub Actions secret. The repository deliberately has no
hardcoded upstream Apple Team ID.

Windows CMD example:

~~~cmd
set APPLE_TEAM_ID=YOUR10CHARTEAM
~~~

The release workflow passes this value to Expo prebuild so the app and
notification extension receive the correct keychain access groups.

## 2. Distribution certificate

Generate a private key and certificate signing request. OpenSSL works on
Windows, macOS and Linux:

~~~bash
openssl genrsa -out irisa-dist.key 2048
openssl req -new -key irisa-dist.key -out irisa-dist.csr \
  -subj "/emailAddress=admin@example.org/CN=IRISA Mail/C=IR"
~~~

Upload irisa-dist.csr at developer.apple.com → Certificates → + → Apple
Distribution. Download the certificate and export it with the private key:

~~~bash
openssl x509 -inform DER -in distribution.cer -out irisa-dist.pem
openssl pkcs12 -export -inkey irisa-dist.key -in irisa-dist.pem \
  -out irisa-dist.p12 -passout pass:CHOOSE_A_PASSWORD
~~~

With OpenSSL 3.x, add -legacy to the pkcs12 export command if required by
macOS Keychain. Keep the private key and P12 password in separate secure
locations. The private key cannot be downloaded again from Apple.

## 3. App IDs and capabilities

Register these explicit identifiers at developer.apple.com →
Certificates, Identifiers & Profiles → Identifiers:

| Target | Bundle ID |
|---|---|
| Main app | ir.irisa.mail |
| Notification service extension | ir.irisa.mail.NotificationService |
| Widget extension | ir.irisa.mail.Widget |

Enable the following capabilities for the main app and the relevant
extensions:

- Push Notifications for the app and notification service extension.
- Keychain Sharing, including the shared group
  $(AppIdentifierPrefix)ir.irisa.mail.shared.

The iOS config plugin adds the shared keychain entitlement and notification
extension metadata. The Apple Team ID must match the prefix used by the
provisioning profiles.

No Associated Domains capability is required for the current custom-scheme
OIDC flow.

### OAuth redirect URIs

Register these redirect URIs in WSO2 and Stalwart as applicable:

- WSO2 sign-in: ir.irisa.mail:/oauth/callback
- WSO2 RP-initiated logout: ir.irisa.mail:/oauth/logout
- Legacy Stalwart native OAuth callback retained for compatibility:
  org.bulwarkmail.mobile:/auth/callback

The WSO2 redirect scheme is registered by app.config.js and the iOS prebuild
configuration. Follow [WSO2-MOBILE-OIDC.md](WSO2-MOBILE-OIDC.md) for the
server-side client settings.

## 4. App Store Connect record and provisioning profiles

Create an App Store Connect app record with bundle ID ir.irisa.mail.

Create an App Store distribution provisioning profile for each signed target:
the main app and the notification service extension. The widget target must
also be covered by the signing configuration generated by Xcode. Download the
profiles and base64-encode them for GitHub Actions.

The release workflow expects the app profile and notification service profile
as separate inputs. It verifies their bundle identifiers before archiving and
exporting the IPA.

## 5. App Store Connect API key

App Store Connect → Users and Access → Integrations → App Store Connect API →
+ . Create a key with the App Manager role. Download the .p8 file (Apple allows
one download only) and record the Key ID and Issuer ID.

## 6. GitHub Actions secrets

In repository Settings → Secrets and variables → Actions, configure:

| Secret | Value |
|---|---|
| APPLE_TEAM_ID | 10-character Apple Developer Team ID |
| IOS_DIST_CERT_BASE64 | Base64 of irisa-dist.p12 |
| IOS_DIST_CERT_PASSWORD | Password used for the P12 |
| IOS_PROVISIONING_PROFILE_BASE64 | App Store profile for ir.irisa.mail |
| IOS_NSE_PROVISIONING_PROFILE_BASE64 | App Store profile for ir.irisa.mail.NotificationService |
| APP_STORE_CONNECT_KEY_ID | App Store Connect API Key ID |
| APP_STORE_CONNECT_ISSUER_ID | App Store Connect Issuer ID |
| APP_STORE_CONNECT_PRIVATE_KEY | Base64 of the .p8 key |

The app and extension profiles must be renewed when their certificates or
profiles expire. Update the corresponding secrets after renewal.

## 7. Build and TestFlight

Publishing a GitHub release triggers the iOS workflow. It can also be started
from Actions → Release iOS (TestFlight). A manual run can build an IPA without
uploading it by turning off upload_to_testflight.

The IPA is uploaded to App Store Connect only when all signing secrets and
profiles are present. Processing can take 5–30 minutes before the build appears
in TestFlight.

The app does not contain an upstream Bulwark TestFlight link. Until IRISA has
its own configured TestFlight listing, the About screen points to the IRISA
GitHub Releases page.

## 8. Push notifications

The native iOS push implementation uses APNs and the notification service
extension. It requires an IRISA-compatible HTTPS relay endpoint configured
through IRISA_PUSH_RELAY_URL. No upstream Bulwark relay is configured by
default.

The APNs authentication key (.p8), Key ID and Team ID are server-side relay
credentials. They must be installed in the IRISA relay; do not embed the APNs
private key in the mobile app or commit it to this repository.

The Android embedded ntfy transport is separate from iOS. iOS uses APNs via
the IRISA relay rather than a persistent ntfy connection.

## 9. Current platform limitations

- Client-certificate authentication is currently implemented only by the
  Android native module. iOS secureFetch falls back to standard fetch.
- In-app binary installation is intentionally disabled on iOS. Updates arrive
  through TestFlight/App Store, consistent with App Store Review guideline
  2.5.2.
- The final IRISA app icon, splash artwork and widget artwork still need
  approved brand assets before production distribution.
